# 🙏 WWJC Bot — What Would Jesus Comment?

**WWJC Bot** is a Chrome extension and AI-powered backend that identifies contradictions using the moral framework of Christian scripture.

Users can highlight any social media post, right-click, and generate a Bible-based comment that challenges the statement using teachings of Jesus and God.

---

## ✨ Features

- 🙏 Context-aware responses based on scripture
- 🖱️ Right-click integration in Chrome to trigger the bot
- 🧠 Backend powered by Mistral LLM via Hugging Face + Modal
- 📖 Structured output:  
  - Bible verse reference  
  - Full verse text  
  - Concise explanation of the contradiction
- 📋 One-click copy to clipboard for easy reply posting

---

## 💡 Why This Exists

WWJC Bot is designed to challenge contradictions between professed Christian values and harmful or exclusionary online behavior.

It holds people accountable using the same belief system they publicly claim — not to preach, but to prompt introspection and ethical consistency.

---

## 🔐 Privacy & Ethics

- No personal data is stored
- No tracking or analytics
- Responses are generated in real time using open-source LLMs
- This is a tool for moral accountability, not harassment

---

## Tech Stack

- **Frontend:** Chrome Extension (HTML/CSS/JS), Manifest V3, plain JavaScript
- **Backend:** an external HTTP service, not part of this repository (see Backend below)
- **Model:** Mistral-7B-Instruct

## Development

Requires Node.js 22.12 or newer.

```sh
npm ci          # install dev dependencies
npm run lint    # ESLint
npm test        # vitest
npm run build   # writes dist/extension/
npm run package # rebuilds dist/extension/ and writes dist/wwjc-extension-<version>.zip
```

To try the extension, run `npm run build`, open `chrome://extensions`, turn on
Developer mode, choose "Load unpacked" and select the `dist/extension/` directory.
Do not load the repository root: it contains `node_modules/` and other files that are
not part of the extension. Run `npm run build` again after changing a source file, then
reload the extension.

`npm run package` produces the zip that is shipped. It contains only `manifest.json`,
`background.js`, `popup.html`, `popup.js`, `icon.png` and the files in `lib/`, copied
unchanged. CI runs lint, tests and the package step on every pull request and on pushes
to `main`, and uploads the zip as a build artifact.

### Using a local backend

```sh
npm run build:dev -- --api-url http://localhost:8000
```

This writes a separate `dist/dev-extension/` directory (load it the same way). In that
copy only, `API_URL` in `lib/request.js` is set to the given URL, the manifest's
`host_permissions` are set to that URL's origin, and the name gets a ` (dev)` suffix.
The committed sources and the packaged zip are not changed. The URL must be `http:` or
`https:` and must not contain a username or password.

## Backend

The comment is generated by an external HTTP service that is not in this repository.
The endpoint is `API_URL` in `lib/request.js`; the manifest's `host_permissions` grant
access to that origin only, and the two must change together.

The extension sends:

```
POST <API_URL>
Content-Type: application/json

{"text": "<selected text>"}
```

A successful response is JSON of the form:

```json
{"raw": {"reference": "...", "verse": "...", "explanation": "..."}}
```

All three fields must be non-empty strings. On failure the service may answer with
`{"error": "<message>"}`, which the popup shows (trimmed and shortened).
